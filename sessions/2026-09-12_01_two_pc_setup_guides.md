# 두 컴퓨터 WSL2 공유 실행 설정 문서

## 현재 상태

- 후속 저장 정책: 사용자 요청으로 메인컴 서브컴 전용 결과 폴더·쓰기 공유 생성 및 실제 권한 검증 완료. 서브컴 mount는 관리자 실행 대기. [현재 저장 계약](../docs/network/sub_results_share.md).

- 확인 기준: 2026-09-12. **문서와 메인컴 공유 설정 완료**, 서브컴 접속·GPU·자동 복구 검증 미완료.
- 후속 사용자 요청으로 Samba 설치·공유·Windows 관리자 전달과 단일 상대 IP 방화벽을 적용했다. 실제 설정·검증·복구 명령은 [메인컴 상태](../docs/network/main_pc_status.md)가 소유한다.
- 사용자 요청: 두 Windows 10 컴퓨터의 Codex가 각각 설정할 수 있는 메인컴·서브컴 문서.
- [메인컴 문서](../docs/network/main_pc_setup.md): Samba 읽기 전용 공유, Windows 포트 전달, VS Code SSH 접속과 자동 복구 계약.
- [서브컴 문서](../docs/network/sub_pc_setup.md): CIFS 연결, SSH, 로컬 Python/캐시/출력, GPU smoke와 본 실행 인계 경계.
- 코드는 메인컴에서 공유하고 서브컴이 직접 읽는다. 환경·캐시·출력은 우선 기기별로 분리하는 설정안을 제시했다.
- 기존 wrapper의 공유 `.venv`·고정 출력 사용을 확인하여 그대로 실행하지 않도록 명시했다. 공통 실행기 변경은 이번 범위에 포함하지 않았다.
- 검증: 문서 링크·fence·개인 경로/secret·공백, 실제 Windows PowerShell 구문 검사와 SMB 인증·hash·쓰기/익명/숨김 경로 거부, Windows→WSL TCP와 방화벽 범위 조회 통과.
- 공식 WSL/Samba 문서는 웹으로 확인했고 실제 패키지 다운로드·설치를 수행했다. 프로젝트 근거는 로컬 snapshot이며 Git fetch·commit·push는 하지 않았다.
- 다음 작업: 공유 암호를 로컬에서 설정하고 서브컴 접속·SSH 계정/공개키·GPU 검증 뒤 자동 복구를 마무리한다.
- 후속 요청: Windows 서브컴 전용 SSH 키 생성·공개키 전달 완료. 개인키/공개키 원문은 기록하지 않으며 서브컴 등록과 실제 접속은 미검증이다.
- 후속 연결 확인: 사용자 host key 지문 확인 후 메인컴 신뢰 등록·서브컴 choi 공개키 로그인 통과. RTX 5070 조회 성공. 공유 마운트/fstab·venv·수치 패키지는 부재하여 계산 준비는 미완료. 상세는 메인컴 상태 문서 참조.
- VS Code 후속: 기존 Remote - SSH 확장·별칭·원격 폴더 접근 재확인 후 서브컴 작업 폴더를 새 원격 창으로 실행. CLI 종료0과 원격 서버 디렉터리/code 프로세스 확인. GUI 완료 표시는 사용자 화면 확인 대상.
- root의 기존 dirty 변경은 보존했다. 하위 세 저장소는 읽기만 했으며 변경하지 않았다.
